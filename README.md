# 歌剧舞台提词台（opera-stage-prompter）

演出期间在多个标签页 / 窗口并存的情况下，保证**舞台上只有一个有效操控者**，
防止旧排练窗口误触导致投影“跳句”。纯前端、单页、**完全离线**：
TypeScript + React + Vite，无任何运行期网络请求。

## 解决的问题与边界

- 节目单（双语字幕 + 黑场提示）可随时编辑、排序、预览；这些只改**草稿**。
  草稿带有单调版本号 `draftRev`：编辑、草稿存档（`draft` 键）与放行快照
  （`frozen` 键）引用同一可追溯版本。
  - 修改经 400ms 防抖自动保存；切页（哈希路由卸载编辑页）或关闭标签页
    （pagehide）时立即把未落盘修改经全局串行队列写盘——快速切页再切回，
    尚未防抖落盘的文字不会消失，重开仍是最新草稿；
  - 两处编辑页从同一版本开始修改时，保存与采用都在 IndexedDB 事务内核对
    `draftRev`：后保存的旧内容**报冲突而不是静默覆盖**对方已确认内容；
    冲突页暂停自动保存、禁用放行，必须显式“载入最新”或“用本页内容覆盖”
    （后者把版本号推进到对方版本之后，保持全局单调）；
  - 一次保存失败后修改不丢（错误保留、不清脏、下次编辑 / 切页 / 放行重试）；
    点“采用”时草稿归档与冻结快照在**同一事务**写入、记录同一 `draftRev`，
    事务失败两者都回滚——未持久化的草稿不可能被冻结为演出版本，不会出现
    “重开草稿与现场版本不一致”的半更新状态。
- 点击 **“采用节目单”** 才把当前内容**快照冻结**为在演版本；空节目单禁止采用。
  采用之后继续编辑不会影响正在演出的版本，直到再次“采用”。
- **演出中重新采用（删减 / 改文案 / 重排）**：采用确认落盘后经 BroadcastChannel
  通知所有**已打开**的控制页（含持锁主控与排队备用页），它们立即丢弃打开时
  缓存的旧条目、重新读取最新冻结快照：
  - 主控的可操作 cue 与最新冻结版本一致，已删除条目与旧文案再无法发布
    （发布事务内以持久冻结快照逐字核对，旧页残留列表也被拦截）；
  - 主控退场后备用页**普通接管**：在同一接管事务里按最新冻结版本裁决沿用画面——
    仍存在且未被改写的最后确认画面继续显示（不闪黑），已删除或已修改的画面
    以黑场（`cueId=null`）进入新代次，绝不把旧节目内容投给观众；
  - “指定并交权”的接权事务使用同一裁决，被指定页接权同样不会复活旧画面；
  - 未采用的草稿只落 `draft` 键，与在演无关；重新采用事务失败（如写盘错误）
    则旧冻结版本与最后有效画面原样保留，不清空、不产生半更新状态。
- **开演页**竞争一把跨页面的 Web Lock（`opera-stage-controller`）：
  - 胜者在**同一个 IndexedDB 读写事务**里取得递增**代次（generation）**
    并写入本代次初始画面（接管时沿用上一代画面，不闪黑）；
  - 其他开演页只能**只读**排队等待，显示当前画面与在任控制者；
  - 控制页关闭 / 崩溃 → 浏览器自动释放锁，排队页自动接管，产生**新一代次**。
- **指定并交权（舞台监督明确交接）**：
  - 每个开演页在页面生命周期内持有**稳定可辨认身份**；排队页经
    BroadcastChannel 声明**在线**，在任控制者从在线候选里选定一页；
  - 点“指定并交权”先把**待交接记录**——来源代次、唯一版本、目标身份、
    **5 秒期限**——**确认写入 IndexedDB 后才释放 Web Lock**（保存失败继续持锁）；
  - 任何取得底层锁的页面都**先按持久状态裁决资格**：
    有效期内只有**目标身份与版本都匹配**的页面能在**同一事务**里
    消费授权、删除记录、开下一代并沿用最后确认画面；
    先排队的非目标（或版本不符）**不改代次地让锁**并继续排队，
    到期自动重新参与普通接管；
  - 目标页关闭 / 崩溃同样不致命：授权 5 秒后失效，排队页照常接管，
    **系统不会停摆**；任意排队页也始终保留“退场交权 / 关闭即接管”的入口；
  - 授权消费、新代次、沿用画面**一次确认**，失败则三者都不变并提示重试；
    授权只能消费一次，迟到的旧在线 / 旧交接消息以来源代次栅栏丢弃。
- 切句 / 黑场：在**同一事务**中
  1. 核对持久代次 == 本页代次（旧代次直接拒绝）；
  2. 核对当前画面控制者 == 本页身份（冒充者拒绝）；
  3. 核对待发布画面属于**最新冻结节目**（条目仍在且文案逐字一致；显式黑场除外）；
  4. 序号（sequence）+1 并整帧落盘；
  事务提交成功后才经 `BroadcastChannel` 发布。
- **一次撤销上一帧**：仅限误切后的当前控制者、当前代次使用。发布普通 cue 或
  普通黑场时，当前帧与“可撤销的前一帧”会在同一 IndexedDB 事务内保存；撤销
  **不是回退序号**，而是把前一帧内容以同代次的更高序号重新发布，并立即消费资格。
  投影端只接受更高序号，因此不会把撤销帧误判为迟到旧画面。撤销事务仍核对代次、
  控制者、当前帧与最新冻结节目；接管、指定交权、重新采用、紧急黑场锁定都会清除
  旧资格。写入失败或旧控制页重试不改变控制台、投影和持久帧，恢复后可重试一次；
  旧库存只有当前帧、没有撤销键时按“不可撤销”读取。
- **紧急黑场锁定**（舞台事故一键持续黑场）：
  - 只有**当前持锁且代次匹配**的控制页可设置：锁定记录（代次 / 身份 / 时刻）
    与“已确认黑场帧”在**同一笔 IndexedDB 事务**里写入，序号 +1，
    **提交成功后才广播**；写入失败时数据库、控制台与投影都停留在上一个
    确认状态，刷新后也绝不出现“画面黑了但锁定丢失”；
  - 锁定期间**切句请求一律拒绝**（字幕、指向具体黑场条目的画面都不行），
    普通“黑场”按钮仍只产生**单帧黑场**，不设置 / 改变 / 解除锁定；
  - 锁定**跨普通接管、指定交权与重新采用持续存在**：接管 / 接权事务读到
    锁定记录时新代次首帧**一律强制黑场**（不沿用旧字幕），记录原样保留；
    **新控制者必须显式解除**后才可继续发布最新冻结节目中的 cue，解除只删
    锁定记录、不改画面（舞台保持黑场直到主控主动切句）；
  - **旧代次页面与迟到消息都不能解除或覆盖锁定**：解除 / 设置同样走代次 +
    控制者 + 同事务核对；`blackout-lock` 广播按来源代次栅栏丢弃旧消息；
  - 锁定是独立持久键，**旧库存记录按未锁定读取**，无需迁移。
- 投影页严格只读，接收规则：**只接受更高代次，或同代次更大序号**。
  失锁旧页的迟到消息（哪怕序号很大）一律丢弃；重开页面时以 IndexedDB
  中最后一幅**已确认画面**为准。
- **写入失败语义**：事务失败则整体回滚，库内与屏幕都停留在上一幅确认画面，
  UI 报错；绝不存在“先报成功、刷新后回退”。
- 失锁瞬间旧页 UI 立即禁用（遮罩 + 按钮失效），其任何后续操作无效。

### 明确不做的事（边界）

- 不做多用户账号 / 鉴权；“唯一性”以**同源浏览器**为界（Web Locks 的作用域）。
- 不做云端同步、不做跨设备协同：锁与持久状态都在本机浏览器内。
- 不主动清除持久数据；节目单与最后画面重开浏览器后仍在（IndexedDB）。
- 浏览器必须同时具备 IndexedDB、Web Locks、BroadcastChannel、structuredClone。
  缺任一项时**编辑照常可用**，页面会逐项列明缺项，并**禁止开演**（不参与锁竞争）。
- 旧版本写入的 IndexedDB（没有交接记录键）天然按“无记录”处理：直接沿用普通竞争。
- 黑场即全黑，不投出任何文字；舞台备注只在控制端可见。

## 本地开发

```bash
npm ci
npm run dev        # http://localhost:5173
```

路由（哈希，无服务端依赖）：

- `#/edit` 编辑 / 排序 / 预览 / 采用节目单
- `#/stage` 开演控制台（竞争唯一锁）
- `#/projector` 投影页（只读，可全屏投到舞台）

验收建议：开 1 个投影页 + 3 个开演页（A/B/C），在 A 的“在线控制页”里
对 C 点“指定并交权”——先排队的 B 不会开代，C 接管为新一代；随后关闭 C，
观察 B 在授权失效后最终接管；投影全程只显示已确认画面。

## 构建与校验

```bash
npm run build      # 类型检查 + 产出 dist/
npm run test:unit  # Vitest：持久状态、草稿版本链、代次事务、消息栅栏、写入失败、交接裁决、紧急黑场锁定、一次撤销上一帧
npm run test:e2e   # Playwright：切页落盘、两处编辑交错冲突、失败后放行、争用接管、指定交权、迟到消息、紧急黑场锁定、连续撤销/黑场/交权/写盘故障
```

## Docker

宿主端口由 `WEB_PORT` 覆盖（默认 `8080`）：

```bash
WEB_PORT=9000 docker compose up --build
# 打开 http://localhost:9000
```

`verify` 是**一次性**校验服务（构建镜像 → Vitest → Playwright → 退出）：

```bash
docker compose build verify
docker compose run --rm verify
# 也可只跑其中一段：
docker compose run --rm verify npm run test:unit
```

镜像分三阶段：`build`（编译）、`runtime`（仅 nginx 静态托管 dist）、
`verify`（含 Chromium 与其系统库）。运行镜像不包含测试依赖。

## 目录

```
src/
  types.ts               领域模型与线协议（含待交接记录、紧急黑场锁定、一次撤销资格）
  lib/db.ts              IndexedDB：单事务开代次/发画面/撤销/冻结/交接/黑场锁定的写入与解除
  lib/locks.ts           Web Lock 排他封装（排队、失锁、非目标不改代次地让锁）
  lib/protocol.ts        纯函数：代次栅栏、交接资格裁决、显式黑场判定
  lib/sessions.ts        控制会话（在线候选/指定交权/紧急黑场锁定）/ 投影只读会话
  lib/capabilities.ts    能力探测（缺项列明、禁止开演）
  lib/useProgram.ts      草稿编辑/排序/防抖持久化（切页即落盘）/draftRev 乐观并发/冲突解决/同版本采用
  pages/                 EditorPage / ControlPage / ProjectorPage
tests/unit              Vitest（fake-indexeddb + 锁/通道桩）
  program.ts             测试便捷工具：以编辑页方式同事务归档+冻结
tests/e2e               Playwright 多页面验收
```
